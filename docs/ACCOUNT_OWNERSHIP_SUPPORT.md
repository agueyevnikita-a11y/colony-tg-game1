# COLONY подтверждение аккаунта для обращения в поддержку

Состояние на 10 ноября 2026 года: механизм развёрнут на RUVDS, версия **1.14.26**, текущий выпуск `/opt/colony/releases/20261110-ownership-proof`. Рабочий образ: `sha256:0d360295d663e10424cb38bf186098a956d7f740df4285424f063ec6aa8d978c`. Это инструкция оператору, а не публичная политика и не разрешение на удаление аккаунта. **Проверка настоящим владельцем через Telegram ещё не выполнена.**

## Назначение

Игрок получает код в Telegram Mini App и указывает его в письме на `colonygamehelpdesk@yandex.com`. Оператор проверяет код и связывает конкретное обращение с существующим игровым аккаунтом.

Код подтверждает доступ к аккаунту через проверенную Telegram-сессию. Он не подтверждает паспортную личность, возраст, родство, полномочия представителя, владение почтовым ящиком или квалифицированную электронную подпись. Код не является согласием на обработку данных, разрешением на выгрузку или удаление и не выполняет эти действия.

По подтверждению владельца, входящая почта доставляется; исходящая почта ограничена. Механизм не отправляет письма автоматически. Порядок ответа на обращения и защищённый реестр нужно довести отдельно.

Если Telegram потерян, аккаунт отсутствует либо код получить не удалось, письмо принимается обычным порядком. Отсутствие кода не отменяет права заявителя. Нельзя автоматически создавать или восстанавливать профиль ради подтверждения.

## Действия игрока

1. Открыть игру заново через её Telegram-бота. Для выдачи кода нужна подписанная сессия не старше 5 минут.
2. Найти блок «Поддержка и вопросы о персональных данных» на закрытом экране либо в настройках игры и нажать «Получить код для обращения».
3. Скопировать код и направить его только на указанную почту поддержки вместе с вопросом. Код не нужно присылать в чат с ИИ, публиковать или передавать посторонним.

Код действует 24 часа от выдачи по серверному времени. Интерфейс показывает окончание срока по времени устройства. Получение нового кода отменяет прежний непроверенный код; потерянный код нельзя восстановить из хеша.

## Действия оператора

1. Зарегистрировать входящее письмо в защищённом реестре обращений в РФ вне Git. Присвоить номер без ФИО, email и иных персональных данных, например `TEST-20261110` для теста. Подтвердить конкретное место хранения реестра и доступы до работы с реальными обращениями.
2. Войти в игру своим административным аккаунтом с новой Telegram-сессией. Открыть «Связи» → «Настройки» и в блоке поддержки раскрыть «Проверить код обращения».
3. Вставить код из письма и номер из реестра. Поле «Номер обращения» допускает от 1 до 64 латинских букв, цифр, дефисов и знаков подчёркивания. Оно служит ссылкой на запись реестра; само по себе не доказывает личность, владение email или принадлежность аккаунта.
4. Нажать **«Проверить и погасить код»**. Успех означает одноразовое погашение; повторная проверка этим кодом не пройдёт.
5. Сохранить результат в защищённом реестре: номер обращения, UUID аккаунта, название колонии, идентификатор подтверждения, время выдачи и проверки, оператора. Время сохранять с часовым поясом либо в UTC. Не переносить туда сам код без необходимости.
6. Отдельно определить содержание требования, полномочия заявителя, допустимый объём ответа и правомерность дальнейших действий по утверждённому порядку обращений. Успешная проверка не означает, что любые будущие письма с тем же номером или адресом автоматически подтверждены.

Результат не экспортируется в постоянный реестр автоматически. Сохранить его нужно до закрытия формы и до очистки временных серверных записей. Истёкший код не принимается задним числом по дате письма; для новой проверки запрашивается новый код.

## Технические границы

| Действие | Реализованное поведение |
| --- | --- |
| Выдача | `POST /api/support/ownership-proof`, JSON `{}`. Только проверенный подписанный `initData`; поиск уже существующего пользователя по Telegram ID. `ensurePlayer` не вызывается. Игровой профиль, прогресс и активность не создаются и не обновляются этой операцией. |
| Секрет | 16 криптографически случайных байтов, 128 бит; код с префиксом `CG` и четырьмя группами по 8 шестнадцатеричных знаков. В таблице хранится SHA-256, исходный код возвращается при выдаче. |
| Срок и перевыпуск | Срок 24 часа. Выдачи одного аккаунта сериализованы; прежние непогашенные коды отзываются. |
| Лимиты выдачи | 3 запроса в час и 20 в сутки на аккаунт. При ограничении учитывать `Retry-After`; не выполнять автоматические повторные выдачи. |
| Проверка | `POST /api/admin/support/ownership-proof`, JSON с `code` и `requestRef`. Проверка подписи и свежести сессии, затем роли администратора до поиска кода в БД. Лимит 30 проверок в час на администратора. |
| Одноразовость | Один `UPDATE` проверяет хеш, срок, отсутствие погашения и отзыва. Возвращаются UUID аккаунта, название колонии, ID подтверждения, даты и номер обращения. |
| Доступ во время закрытия | Действие доступно для подтверждения существующего аккаунта при maintenance; оно не открывает игру и не обходит остальные игровые ограничения. При отсутствии аккаунта код не выдаётся. |
| Передача и ошибки | Код передаётся в теле POST, не в URL. Ответы запрещают кеширование. Запрос ограничен по размеру и допустимым полям; код, `initData`, тело и исключения БД не выводятся обработчиком ошибок. |

## Временные записи и резервные копии

На сервере установлена независимая ежедневная задача [очистки](../scripts/cleanup-ownership-proofs.mjs): записи подтверждений старше 6 суток удаляются; при штатной ежедневной работе это означает хранение до 7 суток. Та же задача удаляет `support-proof:%` rate-limit-бакеты, не обновлявшиеся более суток. Это не зависит от выключенного cron игровых уведомлений. Проверенный запуск завершился с `Result=success`, `ExecMainStatus=0`. Следующий запланированный при проверке 10 ноября запуск — **11 ноября 2026 года, 03:30 UTC / 06:30 МСК**.

Эта задача не удаляет игровые аккаунты, обращения, резервные копии или архивы. Старые серверные и локальные копии остаются предметом отдельной незавершённой процедуры. Срок действия кода ограничивает возможность проверки, но сам по себе не уничтожает запись и все её копии.

При восстановлении БД из снимка могут вернуться прежние значения погашения и отзыва. До возобновления проверки кодов нужно отозвать сохранённые активные коды, чтобы восстановление не вернуло уже использованный код в действующее состояние. Эту меру необходимо включить в порядок восстановления.

## Ручная проверка владельцем без удаления данных

Проверку выполнять на изолированном стенде либо после отдельно подтверждённого развёртывания, используя свой существующий аккаунт. Настоящие коды и результаты с персональными сведениями не помещать в Git или чат с ИИ.

- [ ] Записать тестовое обращение `TEST-20261110` в защищённый тестовый реестр. Зафиксировать среду проверки.
- [ ] Существующим обычным аккаунтом получить код на закрытом экране; убедиться, что игра не открылась и профиль не создан заново.
- [ ] Получить второй код, сохранив оба приватно для проверки отзыва. Всего потребуется две выдачи, что укладывается в часовой лимит.
- [ ] У администратора открыть «Проверить код обращения». Первый код должен отклоняться как заменённый; второй с номером `TEST-20261110` должен успешно погаситься и показать нужный UUID аккаунта.
- [ ] Сохранить результат в защищённом тестовом реестре. Повторная попытка со вторым кодом должна отклоняться как уже использованная.
- [ ] У обычного игрока административная форма отсутствует. Для неподписанного запроса или чужой административной роли должны действовать серверные ограничения, проверяемые техническими тестами.
- [ ] При устаревшей Telegram-сессии действие предлагает заново открыть игру. Не менять серверное время ради проверки срока.
- [ ] Убедиться, что тест не создавал покупок, не выполнял выгрузку и не удалял аккаунт или игровые данные. Отдельно подтвердить readiness и сохранение закрытого режима перед признанием выпуска рабочим.
