# COLONY v1.1 — запуск в Telegram

Версия `1.1.0-beta.1` подготавливает игру к закрытому тесту. Сборка и публикация кода в GitHub сами по себе не создают Telegram-бота, базу данных или публичный сервер.

## 1. Подготовить окружение

Нужны Node.js 22.18+, PostgreSQL 16, бот из [BotFather](https://t.me/BotFather) и хостинг с постоянным HTTPS-адресом. Для production задайте переменные в настройках хостинга либо в игнорируемом `.env.production.local`. Скрипты учитывают `NODE_ENV`; установленные хостингом переменные имеют приоритет над файлами.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Настоящий токен BotFather; только на сервере |
| `BOT_USERNAME` | Username бота без `@` |
| `NEXT_PUBLIC_BOT_USERNAME` | Тот же username, доступный **во время сборки** |
| `DATABASE_URL` | Адрес PostgreSQL с правами приложения |
| `APP_URL` | HTTPS-origin игры без пути, query, пароля и fragment |
| `TELEGRAM_WEBHOOK_SECRET` | Отдельная случайная строка из 32+ символов `A–Z a–z 0–9 _ -` |
| `CRON_SECRET` | Другая случайная строка из 32+ символов для cron |
| `ADMIN_TELEGRAM_IDS` | Положительные числовые Telegram ID администраторов через запятую |
| `ALLOW_DEV_AUTH` | `false` в production |
| `SUPPORT_URL` | Необязательная HTTPS-ссылка на поддержку; иначе `/paysupport` укажет на обратную связь в игре |

Не добавляйте `BOT_TOKEN`, пароли БД, webhook/cron-секреты в переменные с префиксом `NEXT_PUBLIC_`. Секреты не нужны в GitHub Actions: тесты используют временные значения и не отправляют сообщения в Telegram.

Для локального браузерного запуска скопируйте `.env.example` в `.env.local`, настройте БД и явно включите `ALLOW_DEV_AUTH=true`. Этот режим работает только при `npm run dev`.

## 2. Проверить и развернуть приложение

```bash
npm ci
npm run doctor -- --local
npm run typecheck
npm test
npm run db:init
npm run build
npm start
```

`doctor --local` проверяет настройки без сетевых запросов. Он не подтверждает существование бота или работоспособность БД. Не подставляйте реальные секреты в команды командной строки; настройте окружение заранее.

`db:init` применяет накопительную схему в одной транзакции. Для обновления v1.0.1 новая миграция не требуется. Если база ещё на v1.0, перед обновлением примените `db/migrations/011_v1_0_1.sql`. Перед изменением существующей production-базы сделайте резервную копию.

`NEXT_PUBLIC_BOT_USERNAME` встраивается в браузерный код. При смене бота нужна повторная сборка, одной смены runtime-переменной недостаточно.

Для Docker заполните переменные, используемые `docker-compose.example.yml`, включая пароль PostgreSQL, затем выполните:

```bash
docker compose -f docker-compose.example.yml build
docker compose -f docker-compose.example.yml run --rm app npm run db:init
docker compose -f docker-compose.example.yml up -d
```

Терминацию HTTPS настраивает хостинг или обратный прокси. Контейнер приложения обслуживает порт 3000. Для Railway передайте `NEXT_PUBLIC_BOT_USERNAME` на этапе Docker-сборки; команды `db:init`, `doctor` и `telegram:setup` выполняются в окружении запущенного сервиса, где доступна его БД.

## 3. Подключить бота

Сначала проверьте доступность `/api/ready`: он должен вернуть HTTP 200. HTTP 503 означает, что конфигурация или схема БД ещё не готовы. Endpoint не проверяет Bot API и не возвращает значения секретов; подробности покажет `doctor`.

Docker healthcheck использует `/api/health/live`: это только проверка работающего процесса. `/api/health` дополнительно проверяет БД, а `/api/ready` — production-настройки и необходимые поля схемы. Не принимайте успешный liveness за готовность к приглашению игроков.

```bash
# Предпросмотр без изменения Telegram-настроек
npm run telegram:setup

# Применение команд, кнопки меню и webhook
npm run telegram:setup -- --apply

# Полная проверка окружения, БД, бота и webhook
npm run doctor
```

Отдельная команда `npm run telegram:webhook -- --apply` обновляет webhook без настройки команд и меню; без `--apply` она показывает план. Не выполняйте её для чужого или общего бота: у бота может быть только один webhook.

После настройки откройте BotFather → ваш бот → Bot Settings → Configure Mini App и задайте Main Mini App URL равным `APP_URL`. Точное название пункта может отличаться между клиентами. Bot API не заменяет этот шаг. Затем проверьте:

- `/start` в личном чате показывает кнопку открытия COLONY;
- `/help` объясняет начало игры;
- `/paysupport` предлагает способ обратиться по поводу покупки;
- `https://t.me/ИМЯ_БОТА?startapp` открывает игру с подписанным Telegram `initData`;
- ссылки `?startapp=ref_…`, `city_…` и `ally_…` работают после настройки Main Mini App.

Команды в группах не показывают личную кнопку Web App. Страница, открытая обычным браузером в production, предлагает перейти в Telegram. Если сессия истекла, закройте и заново откройте Mini App.

## 4. Уведомления и закрытый тест

Настройте вызов `POST /api/cron/notifications` примерно раз в минуту с заголовком `Authorization: Bearer <CRON_SECRET>`. Укажите секрет в настройках планировщика. GET-запрос не запускает рассылку. Предварительно игрок должен включить уведомления и подтвердить разрешение Telegram; ответ клиента сам по себе не выдаёт боту разрешение.

Администратор может включить `beta_required` и создать ограниченные invite-коды в интерфейсе. Проверьте доступ вторым Telegram-аккаунтом. При необходимости включите maintenance: обычным игрокам будет показан экран обслуживания, администратор сохранит доступ.

## 5. Что проверяется автоматически

`npm test` проверяет игровую логику, Telegram-клиент, авторизацию, webhook и инструменты подготовки запуска без реального Bot API. GitHub Actions дополнительно поднимает PostgreSQL 16, дважды применяет схему, собирает production-приложение, запускает HTTP-сценарии первого входа, собирает Docker-образ и проверяет запуск контейнера от непривилегированного пользователя.

Интеграционные тесты запускаются только с `COLONY_TEST_DATABASE=1` на локальной БД с именем `colony_ci` или `colony_test`:

```bash
npm run test:integration
```

Не включайте этот флаг для production. Автоматические тесты не заменяют проверку реального Telegram-клиента, доставки уведомлений и покупки Stars. Используйте [чеклист v1.1](RELEASE_CHECKLIST_v1.1.md) перед приглашением игроков.

Справка: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Bot API: webhook](https://core.telegram.org/bots/api#setwebhook), [кнопка меню](https://core.telegram.org/bots/api#setchatmenubutton).
