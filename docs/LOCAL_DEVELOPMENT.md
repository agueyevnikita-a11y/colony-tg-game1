# Локальный стенд COLONY на Windows

Стенд запускает текущий код игры в браузере с отдельным PostgreSQL 16. Он не зависит от Railway и не использует рабочую базу, токен бота или реальные покупки.

## Запуск

Открой `COLONY-start.cmd` в папке проекта. После подготовки откроется **http://127.0.0.1:3015**.

Первый запуск загружает официальный архив PostgreSQL 16.15 от EDB, проверяет закреплённую SHA-256 сумму и распаковывает только серверные файлы. Архив занимает около 356 МБ; установщик и системная служба не используются. Требуются Node.js 22.18+ и установленные зависимости (`npm ci`). В этом рабочем каталоге запуск также умеет использовать уже подготовленный переносной Node.js.

В терминале из папки проекта доступны те же действия:

```powershell
npm.cmd run local:start
npm.cmd run local:status
npm.cmd run local:stop
```

`local:setup` отдельно подготавливает и запускает только базу. `local:start` делает это автоматически, поэтому отдельная настройка обычно не нужна. Повторный `local:start` возвращает адрес уже работающего стенда.

## Игра и сохранения

В браузере создаётся тестовый игрок 10001. Пройди приветствие и играй как обычно: строй, исследуй, запускай производство и размещай декор. Ресурсы, время строительства и прогресс обрабатывает настоящий сервер, а не макет интерфейса.

Данные и пароль находятся только в игнорируемой папке `.local-data/local-dev/`. Закрытие браузера не останавливает сервер. Для остановки открой `COLONY-stop.cmd` или выполни `npm.cmd run local:stop`. Повторный запуск сохраняет город. Папку `.local-data` удалять не нужно: в ней находятся сохранения.

На экране видна плашка «COLONY · локальный стенд». Разработка идёт в `next dev`: изменения исходников появляются в браузере без публикации. Telegram SDK на этом стенде не загружается. Stars, настоящие уведомления и ссылки реального бота здесь отключены. Для приёмки входа через Telegram и платежей по-прежнему нужен отдельный тестовый бот с HTTPS-сервером.

## Изоляция

- Приложение слушает только `127.0.0.1:3015`, PostgreSQL — `127.0.0.1:55432`. Локальный процесс запуска использует `127.0.0.1:43116`.
- Имя базы `colony_local`, адреса и порты закреплены кодом. Конфигурация с другим адресом или именем отклоняется.
- `.env` проекта не изменяется. Дочерние процессы получают отдельное окружение с локальной базой и пустыми токенами Telegram, webhook и cron.
- Пароль генерируется для этого стенда; в Git не попадают ни пароль, ни база, ни скачанные инструменты.
- Браузерный вход разрешён только в `NODE_ENV=development`. Защита production не меняется.
- Остановка завершает созданный стендом процесс приложения и его собственный кластер PostgreSQL. Если порт занят другим процессом, запуск сообщает об этом и не останавливает его.

## Диагностика

Статус: `npm.cmd run local:status`. Проверка сервера и базы: **http://127.0.0.1:3015/api/health**. `/api/ready` проверяет production-настройки и на этом стенде ожидаемо сообщает об отсутствии реального бота и HTTPS.

Журналы: `.local-data/local-dev/app.log`, `postgresql.log` и `setup.log`. После сбоя сначала используй `local:stop`, затем `local:start`. Не меняй локальные пароли вручную и не подставляй в конфигурацию адрес Railway.

Полная проверка на этом компьютере: останови игру и выполни `npm.cmd run local:test`. Команда поднимет отдельную базу `colony_test`, проверит повторное применение схемы, типы, модульные тесты, production-сборку и интеграционные тесты API. После проверки PostgreSQL остановится; для игры снова выполни `local:start`. Сохранения в `colony_local` не очищаются. Docker и Railway для этой проверки не нужны. Она не включает Docker-проверку образа из GitHub CI.

Исходный архив: [официальная страница PostgreSQL для Windows](https://www.postgresql.org/download/windows/) → [архивы EDB](https://www.enterprisedb.com/download-postgresql-binaries). Закреплённый URL и контрольная сумма находятся в `scripts/local-dev.mjs`.
